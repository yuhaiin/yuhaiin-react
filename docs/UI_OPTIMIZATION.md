- 浏览器 MSW：320×740 / 375×812 手机、1280×900 桌面；验证日志布局/暂停、抽屉收起与焦点、历史翻页后筛选、规则 503 禁止保存/重试、导入部分失败及失败项重试、Base64 草稿、2000 条连接虚拟化。最后一轮 320px 导入框 296px，弹窗 296px，文档无横向溢出；2000 条连接约挂载 10 行。
- 手机首页图表已实测为 240px；只读节点详情能显示完整长名称。
- 原生未保存确认框在内嵌测试浏览器中阻塞自动化；取消导航、多表单只确认一次、保存中禁止导航及默认打开弹窗等由回归测试覆盖。未把这部分报告为完整浏览器验证。

## 重跑 MSW

```sh
npm run dev:msw
```

访问 `http://127.0.0.1:5175/`。查询参数 `scenario=normal|large|empty|error`，应用路由继续使用 hash。
示例：`http://127.0.0.1:5175/?scenario=large#/docs/connections/v2`。

预览只使用合成数据；未知 API 返回 501；API 拦截覆盖其他主机，避免真实请求。该配置仅用于开发预览，生产入口没有 MSW。当前 mock 覆盖审查场景，不是全部 API 的替代后端。测试端口使用独立 origin，并设置合成认证值及本地主机。

## 仍需后端或真机配合的边界

- 当前后端没有轻量分组计数/节点选项接口，历史/失败记录也没有服务端分页。前端修复分页截断和缓存隔离后，分组节点及历史仍需保留完整响应；未声称彻底解决超大数据集的内存占用。这些接口改造需要后端配合。
- 日志后台暂停会漏掉该时段事件，界面已经明确提示；后端没有历史补取能力。
- 字符容量上限是数据结构边界，不是浏览器 heap 的实测值。未做生产长时间 heap、真机帧率、iOS/Android 软键盘、完整屏幕阅读器或全面 WCAG 验证。
